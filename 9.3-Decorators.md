Have you ever seen a Python function with an `@` symbol perched above it and wondered what strange magic was happening?

```python
@my_decorator
def say_hello():
    print("Hello!")
```

Decorators look mysterious at first, but once you pull back the curtain, they are one of Python's most elegant and powerful features. In fact, decorators are not magic at all—they are just regular Python functions used in a clever way.

### The Real-World Mental Model: Gift Wrapping

Imagine you have a plain coffee mug. You want to give it to a friend as a birthday present:

- You don't smash the mug or redesign how it holds coffee.
- Instead, you **wrap it in decorative gift paper** and stick a shiny ribbon on top.
- When your friend opens the gift, the mug still does its primary job (holding coffee), but the gift wrap added a special presentation and excitement around it.

A **decorator** is like that gift wrap. It is a function that takes another function, adds extra features ("wrapping") before or after it runs, and returns the enhanced function—**all without modifying the original function's source code**.

In this guide, we will break down decorators step by step, from the foundational Python concepts that make them possible to real-world production use cases.

## 1. The Core Prerequisite: First-Class Functions

To understand decorators, you first need to understand a golden rule of Python:

> **In Python, functions are first-class citizens.**

"First-class citizen" is a computer science phrase that simply means **functions are treated like any other regular value** (such as strings, integers, or lists).

Because functions are just objects in Python, you can:

1. Assign functions to variables
2. Pass functions as arguments into other functions
3. Return functions from other functions

### 1. Assigning Functions to Variables

You can assign a function to a new variable name without calling it:

```python
def shout(text):
    return text.upper() + "!"

# Assign the function object itself to a new variable (notice: NO parentheses ())
yell = shout

print(yell("hello"))
print(f"Function name: {yell.__name__}")
```

**Output:**

```text
HELLO!
Function name: shout
```

Notice that `yell` points directly to the `shout` function. Calling `yell()` executes `shout()`.

### 2. Passing Functions as Arguments

Just like you can pass a string or an integer to a function, you can pass another function:

```python
def whisper(text):
    return text.lower() + "..."

def greet(func, name):
    # 'func' is executed inside greet
    message = func(f"Hello, {name}")
    print(message)

greet(whisper, "Alice")
```

**Output:**

```text
hello, alice...
```

## 2. Inner Functions and Closures

The next stepping stone to decorators is understanding **nested functions** (functions defined inside other functions) and **closures**.

### Defining a Function Inside Another Function

In Python, you can define a function inside another function:

```python
def outer_function(msg):
    # inner_function is created inside outer_function
    def inner_function():
        print(msg)

    # We return the function itself, NOT the result of calling it (no parentheses)
    return inner_function

hi = outer_function('Hi')
bye = outer_function('Bye')

hi()
bye()
```

**Output:**

```text
Hi
Bye
```

### What Just Happened? (The Magic of Closures)

Look closely at `outer_function`:

1. When we ran `hi = outer_function('Hi')`, `outer_function` finished executing and exited.
2. Normally, when a function finishes, its local variables disappear from memory.
3. However, `inner_function` **remembered** the value of `msg` (`'Hi'`) even after `outer_function` was completely done!

This mechanism is called a **closure**. An inner function retains access to the variables defined in its enclosing scope, even when the outer function has finished running.

## 3. Building Your First Decorator (The Manual Way)

Now that we know we can pass functions as arguments AND return inner functions that remember variables, let's put the two concepts together.

Instead of passing a string like `msg`, let's **pass a function** to `outer_function`!

### Step 1: The Simplest Decorator Structure

```python
def decorator_func(passed_func):
    def wrapper_func():
        return passed_func()
    return wrapper_func

def display():
    print("Display function")

# Manually wrap the display function
decorated_display = decorator_func(display)
decorated_display()
```

**Output:**

```text
Display function
```

Here is the step-by-step breakdown:

1. We pass `display` (the function object) into `decorator_func`.
2. Inside `decorator_func`, we create `wrapper_func`, which knows how to call `passed_func()`.
3. `decorator_func` returns `wrapper_func`.
4. `decorated_display` is now equal to `wrapper_func`.
5. Calling `decorated_display()` executes `wrapper_func()`, which runs `display()`.

### Step 2: Adding Extra Behavior Inside the Wrapper

Right now, `wrapper_func` only calls `display()`. Let's add extra code to execute before `display()` runs:

```python
def decorator_func(passed_func):
    def wrapper_func():
        print(f'Wrapper function executed this function: {passed_func.__name__}')
        passed_func()
    return wrapper_func

def display():
    print("Display function")

decorated_display = decorator_func(display)
decorated_display()
```

**Output:**

```text
Wrapper function executed this function: display
Display function
```

We just enhanced `display()` with extra logging without changing a single line of code inside `display()` itself. That is the essence of a decorator!

## 4. The Clean Pythonic Way: The `@` Syntax

Writing `decorated_display = decorator_func(display)` every time you want to decorate a function is clunky and repetitive.

Python provides a clean, elegant shorthand using the **`@`** symbol:

```python
def decorator_func(passed_func):
    def wrapper_func():
        print(f'Wrapper function executed this function: {passed_func.__name__}')
        return passed_func()
    return wrapper_func

@decorator_func
def display():
    print("Display function")

display()
```

**Output:**

```text
Wrapper function executed this function: display
Display function
```

### Under the Hood

The `@decorator_func` line is pure **syntactic sugar**. Writing:

```python
@decorator_func
def display():
    print("Display function")
```

is 100% equivalent to writing:

```python
def display():
    print("Display function")

display = decorator_func(display)
```

Python replaces `display` with the wrapped version automatically whenever the script loads.

## 5. Decorating Functions That Take Arguments (`*args` and `**kwargs`)

What happens if our original function takes arguments? Let's see what happens if we use our previous decorator on a function with parameters:

```python
@decorator_func
def display_info(name, msg):
    print(f"Hi, {name}. {msg}")

# Calling this:
# display_info('Pushkar', 'You are awesome!')
# Causes:
# TypeError: decorator_func.<locals>.wrapper_func() takes 0 positional arguments but 2 were given
```

### Why Did This Fail?

Remember: When we call `display_info('Pushkar', 'You are awesome!')`, we are actually calling `wrapper_func('Pushkar', 'You are awesome!')`.

Because our `wrapper_func()` was defined with **no parameters**, Python immediately throws a `TypeError`!

### The Solution: `*args` and `**kwargs`

To allow our decorator to work on **any function**—regardless of whether it takes zero arguments, two arguments, or ten keyword arguments—we give `*args` and `**kwargs` to `wrapper_func`:

```python
def decorator_func(passed_func):
    def wrapper_func(*args, **kwargs):
        print(f'Wrapper function executed this function: {passed_func.__name__}')
        return passed_func(*args, **kwargs)
    return wrapper_func

@decorator_func
def display():
    print("Display function")

@decorator_func
def display_info(name, msg):
    print(f"Hi, {name}. {msg}")

display()
display_info('Pushkar', 'You are awesome!')
```

**Output:**

```text
Wrapper function executed this function: display
Display function
Wrapper function executed this function: display_info
Hi, Pushkar. You are awesome!
```

### What Do `*args` and `**kwargs` Mean?

- `*args`: Collects any arbitrary positional arguments (like `'Pushkar'`, `'You are awesome!'`) into a tuple.
- `**kwargs`: Collects any arbitrary keyword arguments (like `age=25`, `city='New York'`) into a dictionary.
- Passing `*args, **kwargs` inside `passed_func(*args, **kwargs)` unpacks them directly into the original function.

This is the standard, universal blueprint for building function decorators in Python.

## 6. Class-Based Decorators (`__init__` and `__call__`)

In Python, decorators don't always have to be functions. You can also use a **class** as a decorator!

Some developers prefer class decorators because they make it easy to store state, maintain counters, or manage complex configuration.

### How Class Decorators Work

1. **`__init__(self, original_func)`**: Receives the target function and saves it as an instance attribute (`self.original_func`).
2. **`**call**(self, \*args, **kwargs)`**: The special dunder method that makes an instance of the class callable like a function. This replaces `wrapper_func`.

```python
class DecoratorClass(object):
    def __init__(self, original_func):
        self.original_func = original_func

    def __call__(self, *args, **kwargs):
        print(f'Call method executed this function: {self.original_func.__name__}')
        return self.original_func(*args, **kwargs)

@DecoratorClass
def display():
    print("Display function")

@DecoratorClass
def display_info(name, msg):
    print(f"Hi, {name}. {msg}")

display()
display_info('Pushkar', 'You are awesome!')
```

**Output:**

```text
Call method executed this function: display
Display function
Call method executed this function: display_info
Hi, Pushkar. You are awesome!
```

When Python sees `@DecoratorClass`, it initializes a new instance: `display = DecoratorClass(display)`. Then, whenever you call `display()`, Python triggers the class's `__call__()` method.

## 7. Best Practice: Preserving Metadata with `functools.wraps`

There is a subtle trap when writing custom decorators: your original function loses its identity!

Let's see the problem:

```python
def my_decorator(func):
    def wrapper(*args, **kwargs):
        """This is the wrapper docstring."""
        return func(*args, **kwargs)
    return wrapper

@my_decorator
def calculate_total(a, b):
    """Calculates sum of two numbers."""
    return a + b

print(calculate_total.__name__)
print(calculate_total.__doc__)
```

**Output:**

```text
wrapper
This is the wrapper docstring.
```

Because `calculate_total` was replaced with `wrapper`, its name became `"wrapper"` and its docstring was replaced. This breaks introspection, debuggers, and auto-generated API documentation.

### The Fix: `@functools.wraps`

Python includes a decorator specifically designed for decorating wrapper functions: `functools.wraps`.

```python
from functools import wraps

def my_decorator(func):
    @wraps(func)  # Preserves func's identity!
    def wrapper(*args, **kwargs):
        """This is the wrapper docstring."""
        return func(*args, **kwargs)
    return wrapper

@my_decorator
def calculate_total(a, b):
    """Calculates sum of two numbers."""
    return a + b

print(calculate_total.__name__)
print(calculate_total.__doc__)
```

**Output:**

```text
calculate_total
Calculates sum of two numbers.
```

Always use `@wraps(func)` when writing custom decorators in production.

## 8. Stacking Multiple Decorators and Order of Execution

In real-world Python applications, you will frequently see more than one decorator applied to a single function. This is called **stacking** (or chaining) decorators.

```python
@decorator_one
@decorator_two
def my_function():
    pass
```

Understanding how stacked decorators work—and in what exact order they execute—is crucial to avoiding subtle bugs.

### The Mental Model: Russian Nesting Dolls (or Onion Layers)

Think of stacked decorators like Russian nesting dolls (Matryoshka dolls) or gift wrapping a box inside another box:

- The **original function** is the smallest doll in the very center.
- The **bottom decorator** (`@decorator_two`, closest to `def`) wraps directly around the function.
- The **top decorator** (`@decorator_one`) wraps around the entire bundle created by the bottom decorator.

### The Two Phases of Order

Stacked decorators operate in two distinct phases: **wrapping time** and **execution time**.

#### Phase 1: Wrapping Time (Bottom to Top)

When Python compiles your code, it applies decorators from the **bottom up** (inside out):

```python
@decorator_one
@decorator_two
def greet():
    pass
```

Under the hood, Python translates this to:

```python
greet = decorator_one(decorator_two(greet))
```

Notice that `decorator_two` is called first to wrap `greet`. Then, `decorator_one` wraps the result.

#### Phase 2: Execution Time (Top to Bottom, then Bottom to Top)

When you actually **call** `greet()`, execution flows like this:

1. Code **before** the function call in `@decorator_one` runs first.
2. Code **before** the function call in `@decorator_two` runs second.
3. The **original function** `greet()` executes.
4. Code **after** the function call in `@decorator_two` runs.
5. Code **after** the function call in `@decorator_one` runs last.

### Step-by-Step Code Example

Let's see this in action by creating two decorators: `@bold` and `@italic`. We'll include print statements so you can see the exact flow of execution:

```python
from functools import wraps

def bold(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("[Bold] 1. Before calling target function")
        result = func(*args, **kwargs)
        print("[Bold] 5. After calling target function")
        return f"<b>{result}</b>"
    return wrapper

def italic(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("[Italic] 2. Before calling target function")
        result = func(*args, **kwargs)
        print("[Italic] 4. After calling target function")
        return f"<i>{result}</i>"
    return wrapper

@bold
@italic
def greet(name):
    print(f"[Core] 3. Executing original greet({name})")
    return f"Hello, {name}!"

message = greet("Pushkar")
print("\nFinal Result:", message)
```

**Output:**

```text
[Bold] 1. Before calling target function
[Italic] 2. Before calling target function
[Core] 3. Executing original greet(Pushkar)
[Italic] 4. After calling target function
[Bold] 5. After calling target function

Final Result: <b><i>Hello, Pushkar!</i></b>
```

### Why Decorator Order Matters

Order is not just cosmetic—swapping the order changes the behavior of your program.

#### 1. Formatting Difference

If you flip the decorators above:

```python
@italic
@bold
def greet(name):
    ...
```

The output tags reverse to `<i><b>Hello, Pushkar!</b></i>`.

#### 2. Security & Logic in Web APIs

Consider this common pattern in web frameworks like Flask or FastAPI:

```python
@app.route("/admin/dashboard")
@login_required
@admin_required
def admin_dashboard():
    return "Welcome to the Admin Dashboard"
```

Here, the order is critical:

- `@login_required` must run first to ensure there is an active logged-in user.
- `@admin_required` runs second to inspect that user's permissions.
- If you accidentally reversed them, `@admin_required` might attempt to check the role of a user who hasn't even logged in yet, triggering a crash or a security vulnerability!

## 9. Popular Real-World Use Cases of Decorators

Decorators are widely used in Python frameworks (like Flask, Django, and FastAPI) and standard libraries. Here are five of the most popular real-world applications:

### Use Case 1: Execution Timer (Performance Benchmarking)

In production, you often want to measure how long certain functions take to execute (e.g., database queries or heavy calculations).

```python
import time
from functools import wraps

def timer(func):
    """Measures and prints the execution time of a function."""
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.perf_counter()
        result = func(*args, **kwargs)
        end_time = time.perf_counter()
        run_time = end_time - start_time
        print(f"[TIMER] '{func.__name__}' ran in {run_time:.4f} seconds")
        return result
    return wrapper

@timer
def heavy_calculation():
    total = sum(i ** 2 for i in range(1_000_000))
    return total

result = heavy_calculation()
```

**Output:**

```text
[TIMER] 'heavy_calculation' ran in 0.0512 seconds
```

### Use Case 2: Logging Function Calls and Arguments

A logging decorator automatically records what functions are called and with what arguments without cluttering the business logic.

```python
import logging
from functools import wraps

logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")

def logger(func):
    """Logs the function name and arguments whenever it is called."""
    @wraps(func)
    def wrapper(*args, **kwargs):
        args_repr = [repr(a) for a in args]
        kwargs_repr = [f"{k}={v!r}" for k, v in kwargs.items()]
        signature = ", ".join(args_repr + kwargs_repr)
        logging.info(f"Executing '{func.__name__}' with args: ({signature})")

        result = func(*args, **kwargs)
        logging.info(f"'{func.__name__}' returned: {result!r}")
        return result
    return wrapper

@logger
def create_user(username, email, role="user"):
    return {"username": username, "email": email, "role": role, "status": "active"}

user = create_user("pushkar", "pushkar@example.com", role="admin")
```

**Output:**

```text
INFO: Executing 'create_user' with args: ('pushkar', 'pushkar@example.com', role='admin')
INFO: 'create_user' returned: {'username': 'pushkar', 'email': 'pushkar@example.com', 'role': 'admin', 'status': 'active'}
```

### Use Case 3: Caching / Memoization (Speeding Up Expensive Calls)

If a function does an expensive computation with the same inputs repeatedly, you can cache the results in memory so subsequent calls return instantly.

Python has a built-in decorator for this called `@lru_cache` (Least Recently Used cache), but here is how you can write your own:

```python
from functools import wraps

def memoize(func):
    """Caches the return values of a function based on arguments."""
    cache = {}

    @wraps(func)
    def wrapper(*args):
        if args in cache:
            print(f"[CACHE HIT] Returning cached result for {args}")
            return cache[args]

        print(f"[COMPUTING] Calculating result for {args}")
        result = func(*args)
        cache[args] = result
        return result
    return wrapper

@memoize
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print(f"Fibonacci(4) = {fibonacci(4)}")
print(f"Fibonacci(4) again = {fibonacci(4)}")
```

**Output:**

```text
[COMPUTING] Calculating result for (4,)
[COMPUTING] Calculating result for (3,)
[COMPUTING] Calculating result for (2,)
[COMPUTING] Calculating result for (1,)
[COMPUTING] Calculating result for (0,)
[CACHE HIT] Returning cached result for (1,)
[CACHE HIT] Returning cached result for (2,)
Fibonacci(4) = 3
[CACHE HIT] Returning cached result for (4,)
Fibonacci(4) again = 3
```

> **Pro Tip:** In real applications, you can simply use `from functools import lru_cache` and place `@lru_cache(maxsize=128)` on your function.

### Use Case 4: Authentication and Authorization (API Route Protection)

In web development (Flask, Django, FastAPI), decorators are the standard way to protect endpoints so that only authenticated or authorized users can access them.

```python
from functools import wraps

current_user = {
    "username": "pushkar",
    "is_authenticated": True,
    "role": "admin"
}

def login_required(func):
    """Ensures a user is logged in before accessing a route."""
    @wraps(func)
    def wrapper(*args, **kwargs):
        if not current_user.get("is_authenticated"):
            raise PermissionError("401 Unauthorized: Please log in first.")
        return func(*args, **kwargs)
    return wrapper

def admin_only(func):
    """Ensures a user has admin privileges."""
    @wraps(func)
    def wrapper(*args, **kwargs):
        if current_user.get("role") != "admin":
            raise PermissionError("403 Forbidden: Admin access required.")
        return func(*args, **kwargs)
    return wrapper

@login_required
@admin_only
def delete_database_record(record_id):
    print(f"Record #{record_id} successfully deleted.")

delete_database_record(101)
```

**Output:**

```text
Record #101 successfully deleted.
```

Notice that you can **stack multiple decorators** on top of a single function! They execute from the bottom up (closest to the function first).

### Use Case 5: Retry on Failure (Network and API Calls)

When calling an external REST API or database, network blips and temporary timeouts can occur. A retry decorator automatically retries the function before raising an error.

```python
import time
from functools import wraps

def retry(max_attempts=3, delay_seconds=1):
    """Decorator factory that retries a function if an exception occurs."""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            attempts = 0
            while attempts < max_attempts:
                try:
                    return func(*args, **kwargs)
                except Exception as error:
                    attempts += 1
                    print(f"[ATTEMPT {attempts}/{max_attempts} FAILED] Error: {error}")
                    if attempts == max_attempts:
                        print("[RETRY EXHAUSTED] Re-raising exception.")
                        raise
                    time.sleep(delay_seconds)
        return wrapper
    return decorator

# Simulate an unreliable API call
call_counter = 0

@retry(max_attempts=3, delay_seconds=0.5)
def fetch_user_data(user_id):
    global call_counter
    call_counter += 1
    if call_counter < 3:
        raise ConnectionError("Network timeout! Could not reach server.")
    return {"user_id": user_id, "name": "Pushkar", "status": "Connected"}

data = fetch_user_data(42)
print("Fetched Data:", data)
```

**Output:**

```text
[ATTEMPT 1/3 FAILED] Error: Network timeout! Could not reach server.
[ATTEMPT 2/3 FAILED] Error: Network timeout! Could not reach server.
Fetched Data: {'user_id': 42, 'name': 'Pushkar', 'status': 'Connected'}
```

## 10. Quick Reference Summary

Here is a quick cheat sheet to keep in mind when working with decorators:

| Concept                   | What It Means                                                                | Example Syntax                   |
| :------------------------ | :--------------------------------------------------------------------------- | :------------------------------- |
| **First-Class Function**  | Functions can be passed around like any variable                             | `my_var = my_func`               |
| **Closure**               | An inner function remembering variables from the enclosing outer scope       | Inner function accessing `msg`   |
| **Wrapper Function**      | The inner function that surrounds and adds behavior to the original function | `def wrapper(*args, **kwargs):`  |
| **Decorator Shorthand**   | Python's syntactic sugar for `func = decorator(func)`                        | `@my_decorator`                  |
| **Handling Arguments**    | Universal signature to accept and forward any arguments                      | `*args, **kwargs`                |
| **Class Decorator**       | Using a class with `__init__` and `__call__` as a decorator                  | `class DecoratorClass:`          |
| **Metadata Preservation** | Keeping the original function's name and docstring intact                    | `@functools.wraps(func)`         |
| **Stacking Decorators**   | Applying multiple decorators (runs bottom to top)                            | `@dec1`<br>`@dec2`<br>`def f():` |
