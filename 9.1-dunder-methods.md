Have you ever wondered how Python knows what to do when you write `1 + 2`, call `len(["apple", "banana"])`, or print an object with `print(my_car)`?

None of this is secret magic hardcoded into Python. Behind the scenes, **everything in Python is an object**, and all of these everyday operations work through special built-in methods called **dunder methods**.

In this guide, we will break down what dunder methods are, how they work, and how you can use them to make your own custom classes feel just as natural and powerful as Python's built-in types.

## 1. What Are Dunder Methods and Why Do They Exist?

The word **"dunder"** is short for **"Double UNDERscore"**.

Dunder methods are special functions in Python that start and end with two underscores, such as `__init__`, `__str__`, and `__add__`. You might also hear them called **"magic methods"** or **"special methods"**.

### Python's Secret Translator

Whenever you use everyday Python syntax, Python translates your code into a dunder method call under the hood:

- When you write `a + b`, Python secretly runs `a.__add__(b)`
- When you write `len(my_list)`, Python secretly runs `my_list.__len__()`
- When you print `print(my_object)`, Python secretly runs `my_object.__str__()`

Here is proof that Python primitives (like strings) use dunder methods behind the scenes:

```python
# Everyday string concatenation
str1 = "Hello "
str2 = "World!"
print(str1 + str2)

# What Python is actually doing behind the scenes:
print(str1.__add__(str2))
```

**Example Output:**

```text
Hello World!
Hello World!
```

The exact same thing happens with the `len()` function:

```python
str1 = "Good morning!"

# Standard way
print(len(str1))

# Dunder method behind the scenes
print(str1.__len__())
```

**Example Output:**

```text
13
13
```

By defining these same dunder methods inside your own classes, you can teach Python how your custom objects should behave when added, printed, measured, or looped over!

## 2. Object Creation & Initialization: `__init__`

The most common dunder method you will ever write is `__init__`.

When you create an instance of a class, Python automatically calls `__init__` right after creating the object. Think of it as a setup checklist: it assigns initial values to the object's attributes.

### Example: A Simple Rectangle Class

```python
class Rectangle:
    def __init__(self, length, breadth):
        self.length = length
        self.breadth = breadth

# Creating an instance
rect = Rectangle(5, 10)

print(rect.length)
print(rect.breadth)
print(rect)
```

**Example Output:**

```text
5
10
<__main__.Rectangle object at 0x10be3a660>
```

Notice what happens on the last line when we try to `print(rect)`: Python gives us a strange output like `<__main__.Rectangle object at 0x10be3a660>`.

This is Python's default representation of an object. It shows the class name and its memory location, which isn't very helpful for humans. In the next section, we will fix that!

## 3. Making Objects Human-Readable: `__str__` vs `__repr__`

Python provides two primary dunder methods to convert an object into text: `__str__` and `__repr__`.

| Dunder Method | Purpose                                   | Target Audience  | Triggered By                                  |
| :------------ | :---------------------------------------- | :--------------- | :-------------------------------------------- |
| `__str__`     | User-friendly, clean, easy to read        | End users & logs | `print(obj)`, `str(obj)`, `f"{obj}"`          |
| `__repr__`    | Detailed, unambiguous, helps in debugging | Developers       | `repr(obj)`, typing variable in notebook/REPL |

### Improving the Counter Class with `__str__`

Let's look at a `Counter` class that tracks a number. Without `__str__`, printing the counter looks ugly. With `__str__`, it displays cleanly:

```python
class Counter:
    def __init__(self, count):
        self.count = count

    def count_up(self):
        self.count += 1

    def count_down(self):
        self.count -= 1

    # String representation (runs whenever str() or print() is called)
    def __str__(self):
        return f"Count={self.count}"

count1 = Counter(5)
count2 = Counter(10)

count1.count_up()
count2.count_down()

# print() internally calls str(), which triggers __str__:
print(count1)
print(count2)
```

**Example Output:**

```text
Count=6
Count=9
```

### Implementing Both `__str__` and `__repr__` (Best Practice)

For professional code, it is best practice to define both `__str__` (for user readability) and `__repr__` (for developer debugging).

Here is a `Car` class demonstrating both:

```python
class Car:
    def __init__(self, model, year, price):
        self.model = model
        self.year = year
        self.price = price

    # User-friendly representation (clean and readable)
    def __str__(self):
        return f"This is a {self.year} {self.model} car"

    # Debuggable representation (detailed and structured)
    def __repr__(self):
        return f"Car(model={self.model}, year={self.year}, price={self.price})"

my_car = Car("Benz", 2020, 70000)

# Calls __str__
print(my_car)

# Calls __repr__
print(repr(my_car))
```

**Example Output:**

```text
This is a 2020 Benz car
Car(model=Benz, year=2020, price=70000)
```

> **Pro Tip:** If you only implement `__repr__`, Python will use it as a fallback whenever `__str__` is needed. But if you only implement `__str__`, `repr()` will still show the ugly memory address. So if you can only write one, start with `__repr__`!

## 4. Operator Overloading: Doing Math with Custom Objects (`__add__` & More)

In Python, **Operator Overloading** means giving built-in operators (like `+`, `-`, `*`, `==`) custom meanings when used with your own objects.

### Adding Two Objects with `__add__`

What happens if you want to add two `Counter` objects together using `+`? You define `__add__`:

```python
class Counter:
    def __init__(self, count):
        self.count = count

    def __add__(self, other):
        # We check if 'other' is also an instance of Counter
        if isinstance(other, Counter):
            return self.count + other.count
        raise TypeError("Can only add Counter objects to other Counter objects")

count1 = Counter(5)
count2 = Counter(10)

# This triggers count1.__add__(count2)
print(count1 + count2)
```

**Example Output:**

```text
15
```

### Handling Invalid Types Safely

Notice the `isinstance` check in the code above. What happens if someone tries to add a regular integer like `count1 + 5`?

```python
count1 = Counter(5)

# This will trigger the error check
print(count1 + 5)
```

**Example Output:**

```text
TypeError: Can only add Counter objects to other Counter objects
```

By adding type checks inside your arithmetic dunder methods, you prevent invalid operations and provide clear error messages.

### Other Arithmetic Dunder Methods

Python has a dunder method for every single math operator:

| Operator | Dunder Method               | Example Code | What Python Calls Under the Hood |
| :------- | :-------------------------- | :----------- | :------------------------------- |
| `+`      | `__add__(self, other)`      | `a + b`      | `a.__add__(b)`                   |
| `-`      | `__sub__(self, other)`      | `a - b`      | `a.__sub__(b)`                   |
| `*`      | `__mul__(self, other)`      | `a * b`      | `a.__mul__(b)`                   |
| `/`      | `__truediv__(self, other)`  | `a / b`      | `a.__truediv__(b)`               |
| `//`     | `__floordiv__(self, other)` | `a // b`     | `a.__floordiv__(b)`              |
| `%`      | `__mod__(self, other)`      | `a % b`      | `a.__mod__(b)`                   |
| `**`     | `__pow__(self, other)`      | `a ** b`     | `a.__pow__(b)`                   |

### Comparison Dunder Methods

You can also control comparison operators (`==`, `<`, `>`, etc.) using dunder methods:

| Comparison | Dunder Method         | Example Code | What Python Calls Under the Hood |
| :--------- | :-------------------- | :----------- | :------------------------------- |
| `==`       | `__eq__(self, other)` | `a == b`     | `a.__eq__(b)`                    |
| `!=`       | `__ne__(self, other)` | `a != b`     | `a.__ne__(b)`                    |
| `<`        | `__lt__(self, other)` | `a < b`      | `a.__lt__(b)`                    |
| `>`        | `__gt__(self, other)` | `a > b`      | `a.__gt__(b)`                    |
| `<=`       | `__le__(self, other)` | `a <= b`     | `a.__le__(b)`                    |
| `>=`       | `__ge__(self, other)` | `a >= b`     | `a.__ge__(b)`                    |

## 5. Working with Square Brackets `[]`: Collection Dunder Methods

When you work with a Python list or dictionary, you use square brackets `[]` to look up items, change items, delete items, or test if an item is inside using `in`.

You can enable this exact same bracket notation on your own custom classes using these three dunder methods:

- `__getitem__(self, key)`: Gets an item (`obj[key]`)
- `__setitem__(self, key, value)`: Updates or sets an item (`obj[key] = value`)
- `__delitem__(self, key)`: Removes an item (`del obj[key]`)
- `__contains__(self, item)`: Checks membership (`item in obj`)

### Example: A Custom BookShelf Class

```python
class BookShelf:
    def __init__(self):
        self.books = []

    def add_book(self, title):
        self.books.append(title)

    # Enables reading with shelf[index]
    def __getitem__(self, index):
        return self.books[index]

    # Enables updating with shelf[index] = new_title
    def __setitem__(self, index, value):
        self.books[index] = value

    # Enables deleting with del shelf[index]
    def __delitem__(self, index):
        del self.books[index]

    # Enables the "in" operator: "1984" in shelf
    def __contains__(self, title):
        return title in self.books

shelf = BookShelf()
shelf.add_book("The Hobbit")
shelf.add_book("1984")
shelf.add_book("Atomic Habits")

# 1. Reading using __getitem__
print(shelf[1])

# 2. Checking membership using __contains__
print("1984" in shelf)
print("Dune" in shelf)

# 3. Updating using __setitem__
shelf[1] = "Animal Farm"
print(shelf[1])

# 4. Deleting using __delitem__
del shelf[0]
print(shelf[0])
```

**Example Output:**

```text
1984
True
False
Animal Farm
Animal Farm
```

## 6. Managing Resources with `with`: `__enter__` and `__exit__`

You have probably used the `with` statement before when opening files:

```python
with open("notes.txt", "w") as f:
    f.write("Hello!")
```

The reason you don't have to manually call `f.close()` is because the file object is a **Context Manager**. Context managers use two dunder methods under the hood:

1. `__enter__`: Runs automatically right when Python enters the `with` block (used for setup, like opening a resource).
2. `__exit__`: Runs automatically when leaving the `with` block, **even if an error occurred inside the block** (used for cleanup, like closing a file or database connection).

### Example: A Simple Timer Context Manager

```python
import time

class SimpleTimer:
    def __enter__(self):
        print("Starting timer...")
        self.start_time = time.time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        elapsed = time.time() - self.start_time
        print(f"Finished! Execution took {elapsed:.4f} seconds.")
        # Returning False allows any exception inside the block to propagate normally
        return False

with SimpleTimer():
    # Simulating work
    total = sum(i for i in range(1_000_000))
```

**Example Output:**

```text
Starting timer...
Finished! Execution took 0.0245 seconds.
```

Whenever you see a `with` block in Python, you now know that `__enter__` and `__exit__` are doing all the heavy lifting!

## 7. Looping Over Objects: `__iter__` and `__next__`

_(A quick, very simple overview)_

Whenever you write a `for` loop in Python:

```python
for item in my_collection:
    print(item)
```

Python turns `my_collection` into an iterable using two simple dunder methods:

1. `__iter__`: Returns the iterator object itself (getting ready to loop).
2. `__next__`: Grabs the next item one at a time until items run out (raising a `StopIteration` exception when finished).

### Example: A Simple Countdown Iterator

```python
class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        val = self.current
        self.current -= 1
        return val

for num in Countdown(3):
    print(num)
```

**Example Output:**

```text
3
2
1
```

That is all there is to it! `__iter__` sets up the loop, and `__next__` provides each item until `StopIteration` stops the loop.

## 8. More Popular Dunder Methods You Should Know

Beyond what was covered in the notebook, here are three extremely popular and useful dunder methods you will encounter frequently in real-world Python:

### 1. `__len__`: Custom Length for Your Objects

If you want your custom object to work with Python's built-in `len()` function, implement `__len__`:

```python
class Team:
    def __init__(self, name):
        self.name = name
        self.members = []

    def add_member(self, member_name):
        self.members.append(member_name)

    def __len__(self):
        return len(self.members)

team = Team("Engineering")
team.add_member("Alice")
team.add_member("Bob")
team.add_member("Charlie")

print(len(team))
```

**Example Output:**

```text
3
```

### 2. `__call__`: Making an Object Callable Like a Function

If you define `__call__` inside a class, you can call instances of that class just like a normal function with parentheses `()`:

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, number):
        return number * self.factor

double = Multiplier(2)
triple = Multiplier(3)

# Calling the objects like functions:
print(double(5))
print(triple(5))
```

**Example Output:**

```text
10
15
```

This is very popular in libraries like PyTorch (neural network layers) and Flask/FastAPI (callable middleware and dependencies).

### 3. `__bool__`: Defining Truthiness for `if` Checks

In Python, empty lists, zeros, and `None` evaluate to `False`, while non-empty collections evaluate to `True`. You can customize this behavior for your own objects using `__bool__`:

```python
class BankAccount:
    def __init__(self, balance):
        self.balance = balance

    # An account is considered "True" (active) only if balance is greater than 0
    def __bool__(self):
        return self.balance > 0

account1 = BankAccount(250)
account2 = BankAccount(0)

if account1:
    print("Account 1 has available funds.")
else:
    print("Account 1 is empty.")

if account2:
    print("Account 2 has available funds.")
else:
    print("Account 2 is empty.")
```

**Example Output:**

```text
Account 1 has available funds.
Account 2 is empty.
```

## 9. Quick Dunder Cheat Sheet

Here is a quick reference table of the most important dunder methods and how Python triggers them:

| Category           | Dunder Method              | Trigger Syntax                | Description                             |
| :----------------- | :------------------------- | :---------------------------- | :-------------------------------------- |
| **Creation**       | `__init__(self, ...)`      | `MyClass()`                   | Initializes object state and attributes |
| **Representation** | `__str__(self)`            | `print(obj)`, `str(obj)`      | User-friendly string representation     |
| **Representation** | `__repr__(self)`           | `repr(obj)`, interactive REPL | Unambiguous debug string representation |
| **Math**           | `__add__(self, other)`     | `a + b`                       | Addition                                |
| **Math**           | `__sub__(self, other)`     | `a - b`                       | Subtraction                             |
| **Math**           | `__mul__(self, other)`     | `a * b`                       | Multiplication                          |
| **Math**           | `__truediv__(self, other)` | `a / b`                       | Division                                |
| **Comparison**     | `__eq__(self, other)`      | `a == b`                      | Equality check                          |
| **Comparison**     | `__lt__(self, other)`      | `a < b`                       | Less than check                         |
| **Collections**    | `__len__(self)`            | `len(obj)`                    | Returns length or count                 |
| **Collections**    | `__getitem__(self, k)`     | `obj[k]`                      | Access item by key or index             |
| **Collections**    | `__setitem__(self, k, v)`  | `obj[k] = v`                  | Set or update item by key or index      |
| **Collections**    | `__delitem__(self, k)`     | `del obj[k]`                  | Delete item by key or index             |
| **Collections**    | `__contains__(self, x)`    | `x in obj`                    | Check if item exists in collection      |
| **Context**        | `__enter__(self)`          | `with obj:`                   | Enter context manager block             |
| **Context**        | `__exit__(self, ...)`      | Exiting `with`                | Exit context manager block & cleanup    |
| **Iteration**      | `__iter__(self)`           | `for x in obj:`               | Returns iterator for loop               |
| **Iteration**      | `__next__(self)`           | Next loop step                | Returns next element in iteration       |
| **Callable**       | `__call__(self, ...)`      | `obj(...)`                    | Lets object be called like a function   |
| **Truthiness**     | `__bool__(self)`           | `if obj:`                     | Evaluates object to True or False       |
